# AI Failure Mode Audit — Production Studio Drum Kit

Verification date: 9 November 2026, Asia/Saigon. JSON timestamps use UTC: 8 November 2026 at 17:xx UTC corresponds to 9 November 2026 at 00:xx in Vietnam.

## Scope and evidence integrity

This AI-assisted audit verifies three actual defects in Git baseline `067e2d3`, under `lab3/homework1`. The original prompt/response records are unavailable, so individual lines cannot be attributed to a particular author; this report does not claim that AI introduced each defect. The failure modes below describe reasoning and verification gaps to avoid when working with AI. No defects were deliberately inserted into the product to manufacture evidence.

The harness uses the original App.tsx and useDrumKeyboard.ts retrieved from the baseline with git show; supporting assets use the current version. This does not recreate the entire historical environment. Those two files contain all logic relevant to the three defects, and the baseline preparation script is available for inspection. Browser behavior is exercised in headless Chrome.

## B1 — Accessible labels do not satisfy the htmlFor + useId contract

- **Requirement:** every input and meter must have a label htmlFor referencing an ID generated by useId().
- **Baseline location:** App.tsx, the shortcut checkbox, note field, and meter.
- **Reproduction:** open the baseline and inspect input.labels, label.htmlFor, element IDs, and the App source.
- **Observed result:** the checkbox has no ID and its label.htmlFor is empty; the other IDs are constants; useId() is never called. B1 in ai-audit-baseline.json has passed=false.
- **Root cause:** an enclosing label and fixed IDs were used; passing automated accessibility checks was treated as equivalent to meeting the assignment's exact implementation contract. This is an assignment-contract defect, not evidence that the checkbox lacks an accessible name or inherently violates WCAG.
- **AI workflow failure mode:** requesting or trusting a Lighthouse score of 100 without checking each source-level requirement.
- **Correction:** generate three IDs using useId() and share each between the corresponding id and htmlFor. Fix commit: `1014993`.
- **Verification:** B1 in the final results has passed=true; all three controls have explicit labels. The additional functional check confirms that IDs are unique.

## B2 — IME composition events can still trigger drum shortcuts

- **Requirement:** keystrokes used for text composition must not trigger drum shortcuts.
- **Baseline location:** useDrumKeyboard.ts, onKeyDown.
- **Reproduction:** dispatch a keydown KeyboardEvent with code=KeyA, key=a, and isComposing=true to window. This deliberately simulates the event branch; it is not a direct UniKey test.
- **Observed result:** the output changes from the empty-history message to the first Kick hit. Exact UI evidence is `Chưa có lần đánh nào.` (no hits yet) → `Lần 1: Kick` (hit 1: Kick). B2 in the baseline has passed=false.
- **Root cause:** the hook filters repeat events, modifiers, and text-entry targets but omits event.isComposing. The old target filter already blocks events targeting an input; this case specifically checks the composition contract when an event reaches the global listener.
- **AI workflow failure mode:** assuming that event.code and an input-target filter cover every input-method state.
- **Correction:** return early when event.isComposing is true. Fix commit: `041fce6`.
- **Verification:** the same event leaves the output unchanged after correction; B2 in the final results has passed=true. Ordinary shortcuts still pass check-app.mjs.

## B3 — Holding Enter on a focused button produces repeated hits

- **Requirement:** holding an activation key produces one hit, including when a pad has focus.
- **Baseline location:** App.tsx, button onClick; the hook only prevents repetition for letter shortcuts.
- **Reproduction:** focus the Kick pad; call Playwright keyboard.down('Enter') twice, then keyboard.up('Enter'). The second down generates a repeated keydown in the browser, and the native button generates a corresponding click.
- **Observed result:** the first activation shows `Lần 1: Kick` (hit 1: Kick); repetition changes it to `Lần 2: Kick` (hit 2: Kick). B3 in the baseline has passed=false.
- **Root cause:** event.repeat is filtered in the shortcut hook, but native Enter activation reaches onClick without going through the W/A/S/D/J/K/L mapping.
- **AI workflow failure mode:** checking only custom event paths while overlooking native paths that reach the same callback.
- **Correction:** prevent the default action for repeated Enter/Space events in the pad's onKeyDown; retain mouse clicks and initial keyboard activation. Fix commit: `40fa679`.
- **Verification:** the second down still shows `Lần 1: Kick` (hit 1: Kick); B3 in the final results has passed=true. Ordinary Enter, Space, and Tab checks continue to pass.
